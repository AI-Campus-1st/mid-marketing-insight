## 3. 앵커 이벤트 확정 과정 ✅

```
제공 뉴스(제목에 기업명) + 네이버 보강 + 웹 원문
   │ 규칙 기반 사건 묶기: 같은 기업 + 7일 이내 + 제목 유사도 (AI 미사용)
   ▼
사건 묶음 293개
   ├─ 네이버 외 출처 있음 → LLM 1차 판정 (프롬프트 v2) ─┬─ N: 그대로 사용
   │                                                   └─ Y: 전부 사람 확인
   └─ 네이버만 있음 → 사람 판정 (약관)
   ▼
확정 판정 95행 (전부 사람) → 같은 사건 합치기 (기업 + 발표일 3일 이내 + 이름 유사도/같은 유형)
   ▼
고유 이벤트 30개 → 원문 재확인 후 28개
```

## 4. 공시 매칭과 반영 판정 (Day 4) ✅ 합의 (decisions.md)

### 반영 판정 (주 지표) ✅ A·B 합의
```
기준일 d = official_date
d > REFLECTION_CUTOFF(2026-06-30)  → reference (타임라인 표시만, 판정·비교 집계 제외)
기대 보고서 = d 이후 처음 끝나는 보고 기간의 정기보고서
  on_time    : 기대 보고서에 검증된 매칭 있음
  delayed_k  : k번째 이후 정기보고서에서 처음 매칭
  preceded   : 기준일 이전 공시에 계획(L1) 이상 매칭 (공시가 먼저 말함)
  not_found  : 수집 기간 끝까지 매칭 없음 → 화면 표기 "공시에서 미확인" ("미반영" 금지)
보조 지표: lag_days = 첫 매칭 공시 접수일 − d (분포만, 평균 비교 안 함)
```
- **분기보고서에는 연혁·정관이 없다** (B 확인: 34건 중 연혁 33건 생략). 분기 보고서가 기대 보고서인 이벤트는 "II. 사업의 내용"으로만 확인할 수 있으므로, 연혁에서만 나오는 반영은 반기·사업보고서 기준으로 판정된다.

### 매칭 방법
| 단계 | 담당 | 방법 |
|---|---|---|
| 후보 생성 | B (코드) | ① 이벤트명·서비스명 키워드 ② 이벤트 설명 임베딩으로 같은 기업 청크 top-5. 범위: B 의 화이트리스트 섹션, 기준일 −1년 ~ 수집 종료일 |
| 검증 | **공시 담당 B 가 전부** (decisions.md — 처음 계획은 기업별 분담) | 보고서 날짜순으로 읽고 "같은 사건"인지 판정, 반복 문장은 한 번에 처리. 결과를 정하는 행(36행)은 B 가 직접, 나머지는 참고 초안 적용 후 표시. `preceded`·`not_found` 는 B 가 한 번 더 확인 |
| 기록 | | 검증자·판정 이유. 불일치 사례는 회고 자료 |

같은 사건 판정 기준: 같은 기업 / 같은 대상(서비스·조직명이 같거나, 일반 표현이라도 기능·대상이 같음) / 시간 정합(기준일 이후 기간을 다루거나, 이전이면 계획 맥락).

## 5. AI 실행 근거 평가 ✅ (4단계·경계 규칙 합의, [ai_level_guide.md](../ai_level_guide.md))

### 단계 정의 ✅ 4단계(L0~L3)로 확정 — 아래는 검토했던 3개 안
| 안 | 단계 |
|---|---|
| 기획안 (현 `schema.sql`) | 선언 / 계획 / 실행 |
| **설계서 제안 (LLM 이벤트 판정에 이미 사용)** | L0 언급 / L1 계획 / L2 도입·적용 / L3 자체 개발·상용화 |
| 외부 검수 제안 | 선언 / 구축 / 출시 / 운영 / 성과 |

뉴스 쪽 `ai_level_claimed` 는 이미 L0~L3 로 채워져 있다. 공시도 같은 척도를 쓰면 **"뉴스가 주장한 수준 − 공시에서 확인된 최고 수준" = 말-실행 격차**를 바로 계산할 수 있다. 다른 안을 고르면 뉴스 쪽 값을 변환하는 표가 필요하다.

### 근거 3축
| 축 | 출처 | 강도 |
|---|---|---|
| 주장 | 보도자료성 기사 (확정 이벤트의 근거) | 약 |
| 제3자 | 외부 심사 수상, 고객사 발표, 증권사 분석 (제공 뉴스에서) | 중 |
| 실행 | DART 정기보고서 (숫자·고유명사가 있으면 강) | 중~강 |

### AI 워싱 판단 범위
- 판단 가능: 회사가 주장한 수준과 공시로 확인되는 수준의 **격차**
- 판단 불가: 의도, 위법성, 실제 기술력, 매출 기여도
- 화면 용어: "AI 워싱" 대신 **"말-실행 격차"**, "근거 확인됨 / 일부 확인 / 공시에서 미확인"

### 대조군: 두지 않음 (Day 2 결정)
- 에코마케팅은 기획안에서 '선택' 대조군이었다. 뉴스 쪽만 넣고 공시(B)는 기획안대로 5개사만 수집해 기준이 어긋났고, 2026-03 베인캐피탈 공개매수로 상장폐지 절차가 진행돼 공시 비교 조건도 맞지 않을 가능성이 있어 **제외**했다.
- 리포트 한계에 "대조군 없이 5개사 사례 분석"으로 적는다.

## 6. 스키마 v2 제안 ✅ (`event_dart_mapping` 합의 — B 가 `schema.sql` 에 추가)

현재 `schema.sql` (PR #2) 은 그대로다. 아래는 확정 이벤트 파일 형식에 맞춘 제안이다.

```sql
-- documents.news_origin: 'provided' / 'supplement' → 'provided' / 'naver' / 'web'
--   (네이버 원본은 삭제했으므로 DB 에는 provided 와 web 만 적재될 수 있음)

-- ai_events: anchor_events.csv 와 같은 형식
CREATE TABLE ai_events (
    event_id          TEXT PRIMARY KEY,        -- 'E001' …
    corp_code         TEXT NOT NULL REFERENCES companies(corp_code),
    event_name        TEXT NOT NULL,
    event_type        TEXT CHECK (event_type IN ('launch','organization','adoption','investment',
                                                 'partnership','patent','campaign','award')),
    official_date     TEXT NOT NULL,           -- 사람이 확인한 발표일
    ai_level_claimed  INTEGER CHECK (ai_level_claimed BETWEEN 0 AND 3),
    analysis_scope    TEXT NOT NULL CHECK (analysis_scope IN ('judge','reference')),
    primary_source_url TEXT,                   -- 언론사 원문
    search_terms      TEXT                     -- 공시 매칭용 키워드 (JSON), Day 4 에 채움
);

-- 이벤트 ↔ 공시 청크 매칭 (후보 → 검증)
CREATE TABLE event_dart_mapping (
    event_id      TEXT NOT NULL REFERENCES ai_events(event_id),
    chunk_id      TEXT NOT NULL REFERENCES disclosure_chunks(chunk_id),
    rcept_no      TEXT NOT NULL,
    rcept_date    TEXT NOT NULL,
    report_kind   TEXT CHECK (report_kind IN ('annual','half','quarter','major','other')),
    match_method  TEXT CHECK (match_method IN ('keyword','embedding','manual')),
    match_score   REAL,
    ai_level      INTEGER CHECK (ai_level BETWEEN 0 AND 3),
    verified      INTEGER,                     -- NULL 미검증 / 1 같은 사건 / 0 다름
    verified_by   TEXT,
    PRIMARY KEY (event_id, chunk_id)
);
-- 반영 판정·시차는 저장하지 않고 뷰로 계산 (규칙이 바뀌어도 재계산 불필요)
```
- 처음 제안했던 `event_evidence`(이벤트 ↔ 뉴스 기사) 테이블은 **빼도 된다.** 근거 기사의 대부분이 삭제한 네이버 데이터이고, 이벤트별 근거는 `primary_source_url` 하나로 충분하다.
- `disclosure_chunks.ai_stage` → `ai_level`(0~3, + `has_outcome_figure`), `ai_events.first_stage` → `first_level`(+ `ai_level_claimed`) 은 **반영 완료** (Day 2).

## A·B 공유 데이터 규칙
1. 기업 키는 `corp_code` 하나만 쓴다 (기업명 문자열 조인 금지)
2. 날짜는 `YYYY-MM-DD`(KST), 공시는 접수일 기준
3. 뉴스 집계는 `news_origin = 'provided' AND is_duplicate = 0`
4. 이벤트는 `analysis_scope = 'judge'` 만 반영 판정·기업 비교에 쓴다

| Day 1 | 뉴스 중복 판단에 원문URL 미사용 | 서로 다른 기사에 같은 URL이 들어간 사례 23개 확인 | URL 기준 |
| Day 1 | 제공 뉴스 수집 기간 = 2023-10-19 ~ 2026-10-19 확인. 결론 예시의 급증 시점을 "2023년 초"에서 "2024년 4월"로 수정 | 2023년 초는 수집 기간 밖. AI 마케팅 기사가 2024-03 48건 → 2024-04 121건으로 급증 후 유지 | |
| Day 1 | 공시 수집 기간 = 2023-10-19 ~ 2026-10-19 | 뉴스와 시점 비교를 위해 기간 정렬 | |
| Day 1 | 앵커 이벤트용 기사를 보강 수집하고 `documents.news_origin`('provided' / 'supplement')으로 구분 | 제공 뉴스가 키워드 기준이라 기업 이벤트 기사가 부족함 (나스미디어 유해광고 필터링 0건, 제일기획 베리에이드 첫 보도 2026-04-07 누락). Q1·Q2 집계에는 'provided'만 써서 왜곡 방지 | 제공 뉴스만 사용 (나스미디어 시차 분석 제외) |
| Day 1 | 보강 기사는 코드로 수집: 네이버 검색 API(NAVER API HUB)로 후보 검색 → 언론사 원문에서 전문 추출 | 재현 가능한 수집 과정이 필요하고, 제공 뉴스(n.news.naver.com)와 같은 출처. 네이버 검색 API는 2026-07-31부터 개발자센터 신규 신청이 중단되어 API HUB(NCP)에서 발급 | 웹 검색으로 수동 정리 (재현 불가, 웹 검색으로 찾은 7건은 검증용 정답지로 보관) |
| Day 1 | 네이버 뉴스 페이지 크롤링, 구글 뉴스 RSS 미사용 | 두 사이트 모두 robots.txt가 해당 경로를 막고 있음 (n.news.naver.com·search.naver.com `Disallow: /`, news.google.com `/rss/`·링크 변환 경로 비허용) | 구글 뉴스 RSS (키 불필요, 검색어 12개 기준 177건 확인) |
| Day 2 | 네이버 보강 기사는 **AI 미사용·사람 판정·21일 내 원본 삭제** 원칙으로만 사용 | NAVER API HUB 약관(2026-09-20 시행)이 검색 결과·파생물의 AI 입력·학습·평가와 복사·저장·캐싱을 제한(예외: 이력 조회 목적 최대 21일). 이벤트 발견에는 유용하므로 규칙 기반 묶기 + 사람 판정으로만 쓰고, 확정 이벤트는 1차 출처(뉴스룸·언론사 원문) URL로 기록. 수집일 2026-11-13 → 원본 삭제 기한 2026-12-04 무렵 | 네이버 데이터 전면 제외 / 대시보드 결과를 AI에 넣는 우회 (파생물도 제한 대상이라 기각) |
| Day 2 | 기업 뉴스룸(제일기획·이노션·인크로스·나스미디어)을 1차 출처로 수집 | 공식 발표일 확보, 회사 주장의 원문. robots.txt 전체 허용, 수집 금지 약관 없음(Copyright 표시만 있음 → 본문 전문 비공개). 기간 내 281건(제목에 AI 27건). 플레이디·에코마케팅은 자체 뉴스룸 없음 | 뉴스룸 미사용 |
| Day 2 | 뉴스룸·보도자료는 "주장" 근거로만 사용, 실행 판정은 공시에서만 | 회사의 말로 회사의 말을 검증하는 순환 논리 방지. 근거 3축: 주장(뉴스룸·보도자료) / 제3자(수상·고객·증권사, 제공 뉴스에서) / 실행(DART) | |
| Day 1 | 원문 수집 시 robots.txt 확인, 사이트별 1초 간격, HTML 저장본 재사용, 본문 추출은 trafilatura | 사이트 규칙 준수와 재실행 시 중복 요청 방지. 테스트 7건 전부 허용·추출 성공 | BeautifulSoup 사이트별 파서 |

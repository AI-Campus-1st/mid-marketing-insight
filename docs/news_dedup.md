## 1. 제공 뉴스 (`collect/load_news.py`)

### 결과
| 단계 | 건수 |
|---|---|
| 입력 (묶음 CSV) | 6,469 |
| 중복 표시 (`is_duplicate = 1`) | **19** (규칙 ① 13 + 규칙 ② 6) |
| **집계 대상 (`is_duplicate = 0`)** | **6,450** |
| 그중 본문 없음 (`body IS NULL`) | 2 (Q1 기사량에는 포함, Q2 LLM 분석에서는 제외) |

**행을 지우지 않는다.** 6,469건이 모두 `documents` 에 있고 `is_duplicate` 로만 표시한다. 가장 이른 기사 하나가 `0`, 나머지가 `1`.

### 비교에 쓰는 값
| 값 | 만드는 방법 |
|---|---|
| `title_norm` | 제목 앞의 괄호 머리말(`[속보]`, `(종합)` 등)을 지우고, 한글·영문·숫자만 남기고, 영문은 소문자로 (`collect/supplement_search.normalize_title`) |
| `body_hash` | 본문의 연속 공백을 하나로 줄인 뒤 SHA-1 해시. 본문이 없으면 NULL |

### 규칙 (위에서부터 적용, 가장 이른 기사만 남김)
| 규칙 | 조건 | 의미 | 건수 |
|---|---|---|---|
| ① | 같은 `title_norm` **+ 같은 `body_hash`** | 글자 하나 다르지 않은 같은 기사. **매체가 달라도** 본문이 똑같으면 중복 (보도자료를 그대로 붙여 넣은 경우) | 13 |
| ② | 같은 **매체** + 같은 `title_norm` + **24시간 이내** | 같은 매체의 수정·재송고 기사 (본문이 조금 다름). 처음엔 7일이었으나 사람 검수(24쌍) 후 24시간으로 줄임 (`decisions.md` 중복 규칙 행) | 6 |

**예시**
```
규칙 ① (다른 매체, 본문 동일)
  N01472  0  2024-10-28 09:19  연합뉴스      HSAD AI 아트디렉터, AI로 만든 영화로 'AI 국제영화제' 수상
  N01483  1  2024-10-28 17:37  파이낸셜뉴스  HSAD AI 아트디렉터, AI로 만든 영화로 'AI 국제영화제' 수상

규칙 ② (같은 매체, 다음 날 재송고)
  N00194  0  2023-12-13 19:55  MBN  가상 피팅부터 소리 인식 판촉까지…이제는 'AI 마케팅 시대'
  N00195  1  2023-12-14 09:15  MBN  가상 피팅부터 소리 인식 판촉까지…이제는 'AI 마케팅 시대'
```

### 중복으로 보지 않는 것
| 경우 | 이유 |
|---|---|
| **다른 매체가 같은 보도자료를 조금씩 고쳐 실은 기사** (본문이 다름) | 매체별 보도는 언론 노출량이라 기사량에 포함. 같은 정규화 제목 474건(197그룹) 중 대부분이 여기에 해당 |
| 원문 URL 이 같은 기사 | 제공 데이터에서 **서로 다른 기사에 같은 URL** 이 들어간 사례 23개가 있어 URL 은 기준으로 쓰지 않음 |
| 같은 매체·같은 제목이지만 24시간 넘게 떨어진 기사 | 다른 날 다시 실은 기사는 별도 노출로 셈 (사람 검수에서 39시간·5일·7일 뒤 재게재를 '다른 기사'로 판정) |

```
다른 매체 재배포 (모두 is_duplicate = 0)
  N03810  2025-11-10 10:02  조선비즈  프레인글로벌, 글로벌 PR 얼라이언스 'PGA플러스' 출범
  N03812  2025-11-10 10:41  세계일보  (같은 제목)
  N03814  2025-11-10 11:04  비즈워치  (같은 제목)
  N03816  2025-11-10 11:13  뉴스1    (같은 제목)
```

**알려진 비대칭:** 규칙 ① 때문에 "다른 매체 + 본문 완전 동일"은 빠지고, "다른 매체 + 본문 조금 다름"은 남는다. 영향은 13건(0.2%)이라 Q1 추이에는 의미 있는 차이가 없다. 매체별 노출량을 엄밀히 세려면 규칙 ① 에 "같은 매체" 조건을 더하면 된다.

### 확인 방법 (SQL)
```sql
-- 중복으로 표시된 19건과 같은 제목의 남긴 기사를 함께 보기
SELECT d.title_norm, d.doc_id, d.is_duplicate, d.published_date, d.media, d.title
FROM documents d
WHERE d.source_type = 'news'
  AND d.title_norm IN (SELECT title_norm FROM documents WHERE source_type = 'news' AND is_duplicate = 1)
ORDER BY d.title_norm, d.published_date;

-- 집계 대상 건수
SELECT COUNT(*) FROM documents WHERE source_type = 'news' AND news_origin = 'provided' AND is_duplicate = 0;  -- 6450
```
CSV 로 보려면 `data/processed/news_provided_loaded.csv` (집계 대상 6,450건, A 로컬) 를 쓰면 된다.

## 2. 네이버 보강 뉴스 (앵커 이벤트 발견용, 원본 삭제됨)

`collect/supplement_search.py` → `collect/supplement_fetch.py` → `analysis/event_review_sheet.py`
원본(검색 응답·후보 목록·원문)은 NAVER API HUB 약관의 저장 제한 때문에 2026-11-16 삭제했다. **아래 수치와 규칙만 남아 있고, DB 에는 들어가지 않았다.**

### 단계별 건수
| 단계 | 규칙 | 남은 건수 |
|---|---|---|
| 검색 응답 | 검색어 16개 (기업명 + 이벤트명 11개, 기업명 + AI 5개), 최신순, 검색어당 최대 1,000건 | 6,969 |
| 기간 필터 | 2023-10-19 ~ 2026-10-19 | 6,193 |
| **중복 ① 검색어 안** | 같은 검색어 결과에서 `title_norm` 이 같으면 가장 이른 기사만 | 5,648 (545건 제거) |
| 기업 필터 | 제목에 기업명 (`나스미디어` 처럼 옛 표기 포함) | 1,441 |
| 관련 필터 | 이벤트 검색어 결과는 전부, 넓은 검색어(`기업명 AI`) 결과는 제목에 AI 용어가 있을 때만 | 784 |
| **중복 ② 검색어 사이** | 여러 검색어에 같은 제목이 나오면 가장 이른 기사만 | 629 |
| **중복 ③ 제공 뉴스와** | 제공 뉴스에 같은 `title_norm` 이 있으면 제외 (본문이 이미 있음) | 561 |
| 원문 수집 | robots.txt 허용 + 본문 추출 성공 | 536 |

### 사건 단위 묶기 (중복 제거가 아니라 "같은 사건" 묶기)
| 단계 | 규칙 | 결과 |
|---|---|---|
| 사건 묶음 | 제공 뉴스(제목에 기업명) + 네이버 보강 + 웹 원문을 합쳐서, **같은 기업 + 묶음 첫 기사로부터 7일 이내 + 제목 3글자 조각 유사도 ≥ 0.25** 면 같은 묶음 | 기사 781건 → 묶음 293개 |
| 이벤트 판정 | 묶음마다 이벤트 여부 판정 (LLM v2 + 사람 확인) | 이벤트 판정 95행 |
| 같은 이벤트 합치기 | **같은 기업 + 발표일 3일 이내 + (이벤트명 유사도 ≥ 0.3 또는 같은 유형)** | 30개 |
| 원문 재확인 | 제목만으로 판정한 23개를 원문으로 다시 확인, 2개 제외 | **28개** (E001~E028) |

### 수치 정정
`decisions.md` 의 네이버 원본 삭제 행에 "응답 5,969건 → 기간 내 5,648"로 적었는데, 5,969건은 **검색어 14개였던 첫 실행** 수치였다. 최종(검색어 16개) 기준은 위 표가 맞다: 응답 6,969 → 기간 내 6,193 → 검색어 안 중복 제거 후 5,648.
